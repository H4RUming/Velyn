# Velyn v1.2.0

Velyn now uses a camera-adapted GMNet model for SDR-to-HDR prediction. New gain maps apply the learned brightness adjustment at full strength, with midtone protection available when you want a subtler result.

## Changes

- **Fine-tuned HDR model.** GMNet was adapted using native camera HDR/SDR pairs. Both the 512px and 1024px models are bundled; no runtime download or photo upload is needed.
- **Neural Engine preferred.** Eligible devices use a calibrated 1024px model for larger photos. A 512px model provides the fallback. The global branch stays FP32 to avoid the numerical drift seen with full FP16 conversion.
- **Defaults match the learned prediction.** New maps use 100% strength, a 5× gain ceiling, bilinear enlargement, and midtone protection off. The ceiling is a limit, not a fixed boost applied to every pixel. Strength, maximum gain, and protection remain adjustable.
- **Existing edits are preserved.** Stored gain maps retain their rendering. Regeneration keeps your strength, cap, and protection settings. To try the new model and defaults on an older edit, select **Predict gain map again**, then **Full model gain**.
- **Signed gain maps remain supported by the engine.** Experimental maps can represent dimming as well as brightening. The bundled GMNet still predicts positive gain; there is no new dimming model in the app.

## Quality and limits

On 132 previously examined comparison photos, mean luminance error fell from **0.488 EV to 0.328 EV** for direct model predictions. This is a repeated comparison, not an independent final test. The model improved 95 photos and regressed on 37.

A separate check through the actual app engine on eight photos from that collection reduced mean error from **0.469 EV to 0.285 EV** against the previous app defaults. Six photos improved; two regressed, with a worst increase of 0.624 EV. Results can still be too bright or differ from native HDR. These Mac measurements do not establish physical iPhone HDR display quality.

## Download and install

**Requires iOS 27 or later and an arm64 iPhone.**

- Download **`Velyn-1.2.0-unsigned.ipa`** and sign it with your own Apple identity. AltStore Classic is one documented option. Apple Configurator requires an already signed IPA.
- Follow **`INSTALL.md`** attached below or the [installation guide](https://github.com/H4RUming/Velyn/blob/v1.2.0/Docs/Releases/INSTALL.md).
- Download `SHA256SUMS.txt` alongside the IPA and run `shasum -a 256 -c SHA256SUMS.txt`.

The public bundle ID is `com.h4ruming.velyn`. Keep the same bundle ID and signing identity when updating. **Do not delete the app to update it without preserving your originals first:** Velyn's internal photo storage is excluded from system backups.

## Verification

- **83 engine tests pass**, including actual model inference, neutral RGB, HDR JPEG/HEIC output, SDR base preservation, signed maps, cancellation, and legacy editing compatibility.
- Simulator and signed iPhone Release builds pass. The unsigned archive is checked for version **1.2.0 (5)**, arm64 architecture, bundled models/localizations, ZIP integrity, and absence of personal signing material.
- See the [release verification record](https://github.com/H4RUming/Velyn/blob/v1.2.0/Docs/Evidence/v1.2-release-verification.md) for the physical iPhone installation result. AltStore and Configurator have not been tested end to end for this release.

All app photo processing stays on-device. Private training photos and the training checkpoint are excluded from the repository and release; converted inference weights retain GMNet's MIT attribution. Broader camera coverage, device heat/latency, and physical HDR display acceptance remain open.
